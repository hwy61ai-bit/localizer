## CRITICAL: Key Technical Decisions Tim Needs To Know

### 1. Drive Times Use Mapbox — Not Google Maps, Not Estimates
All drive times and distances in TourRouter are powered by **Mapbox Directions API** — not Google Maps, not haversine estimates. This is live and production-ready.

- **What this means:** Every leg in the routing table shows real road distance and drive time, not straight-line estimates.
- **How it works:** When a tour loads, the routing page calls `POST /api/tourrouter/drive-info` for each leg. Results are cached in the `drive_cache` Supabase table (keyed by city pair). Cache never expires — once a city pair is looked up, it's free forever after.
- **Fallback:** If Mapbox fails or a city isn't found, haversine (straight-line) distance is used as a silent fallback. The routing table will still show a number, it'll just be slightly less accurate.
- **Key file:** `lib/tourrouter/mapbox.ts`
- **API route:** `app/api/tourrouter/drive-info/route.ts`
- **Cache table:** `drive_cache` in Supabase

### 2. Flight Prices Use Claude + Web Search
Flight price estimates are generated by Claude using the web_search tool. Results are cached in `flight_price_cache` (keyed by route + date + pax count). Cache expires after 7 days.

### 3. calcTourFinancials() Is The Single Source of Truth
**Never calculate financial totals anywhere else.** Every number in the routing table stat cards, the financials page, and the finance report comes from one function: `calcTourFinancials()` in `lib/tourrouter/financials.ts`. If you want to add a new expense type to the totals, it goes in this function.

## Financial Calculation Engine

### calcTourFinancials() — What It Calculates
Located in `lib/tourrouter/financials.ts`. Takes a `FinancialParams` object and returns `FinancialResults`.

**Expense components (all roll into totalExpenses):**
1. `totalFuel` — estimated fuel cost per leg (multi-vehicle or single vehicle formula)
2. `totalFlights` — flight costs from cache for fly legs
3. `totalManual` — manually entered per-show expenses
4. `totalBlanketShow` — blanket show day payroll (only when no roster)
5. `totalBlanketOff` — blanket off day payroll (only when no roster)
6. `totalPersonnel` — roster-based personnel pay (replaces blankets when roster exists)
7. `totalHotel` — **NEW** hotel costs via three-state waterfall (see below)

**Income:** `totalIncome` — sum of all show income via `calculateShowIncome()` (14 deal types)

**Key outputs:** `totalIncome`, `totalExpenses`, `netIncome`, `margin`, `avgPerShow`, `totalHotel`, `hotelCostByState`

### Hotel Cost Three-State Waterfall (NEW — April 8, 2026)
For each show, hotel cost is calculated in priority order:

1. **State 1 — Actual receipt** (`hotel_cost_actual` on tour_shows): When a hotel receipt is dropped via drag-and-drop, the total is parsed and written here. Multiple receipts stack additively. This number takes full priority.

2. **State 2 — Confirmation estimate** (`hotel_rate × hotel_rooms × nights`): When a hotel confirmation is dropped, the confirmation rate, rooms, check-in, and check-out are parsed and stored. Estimated cost = rate × rooms × nights.

3. **State 3 — Planning projection** (artist lodging defaults + market rate table): Uses the room count and star rating from the Artist Profile Lodging section, combined with `HOTEL_MARKET_RATES` in `constants.ts` (130+ cities) or `HOTEL_FALLBACK_RATES` by region.

**Result fields:**
- `totalHotel` — total hotel cost across all shows
- `hotelCostByState.actual` — how much is from real receipts
- `hotelCostByState.confirmed` — how much is from confirmations
- `hotelCostByState.projected` — how much is estimated from market rates

### Personnel Pay
Located in `lib/tourrouter/personnelPay.ts`. Supports 8 pay structures:
per_show, per_day, per_diem, weekly, flat_tour, percentage_net, percentage_gross, percentage_merchandise

When a `tour_roster` array exists on the tour, `calculatePersonnelCosts()` replaces the flat blanket amounts entirely. Roster pay feeds into `totalPersonnel` → `totalExpenses`.

### Deal Types
Located in `lib/tourrouter/calculateShowIncome.ts`. Supports 14 deal types including flat guarantee, versus deals, percentage of gross/net, sliding scale, bonus thresholds, and more.

## The Artist Profile Lodging Section (NEW — April 8, 2026)

A new **Lodging** accordion section sits between Roster and Vehicles & Equipment on the Master Artist Profile page.

**What it stores (in `artists.lodging_defaults` JSONB column):**
- Room breakdown: array of `{ type, bed_config, count }` (e.g. "TM Single / 1 king / 1 room", "Band Double / 2 queens / 3 rooms")
- Star rating minimum: 2, 3, 4, or 5
- Nightly budget override: optional flat rate that overrides market rate lookup

**How it flows into tours:**
When a new tour is created for an artist, `lodging_defaults` is automatically copied from the artist into the tour record (`tours_routing.lodging_defaults`). The TM can override the nightly rate per tour via `hotel_budget_override` on the tour.

## Drag-and-Drop Document Intake

### How It Works
The entire routing page is a drop zone. Drop any document anywhere on the page — no drawer needs to be open.

**Four steps:**
1. **Detect** — lightweight Claude call identifies document type (advance sheet, hotel confirmation, deal memo, settlement, receipt, etc.)
2. **Match** — Claude matches the document to a show by date + venue + city. Confidence score shown in review screen (green = high confidence, amber = low confidence)
3. **Parse** — full Claude call extracts all fields with per-field confidence scores
4. **Review** — TM sees all extracted data in a review screen, can edit before confirming. Never writes to DB without confirmation.

**What each document type writes:**
- **Advance sheet** → `load_in_time`, `soundcheck_time`, `doors`, `showtime`, `curfew`, `age_limit`, `venue_wifi_name`, `venue_wifi_password`, `parking_notes`, `venue_notes`, `backline_notes`, `production_contact` + phone/email, `settlement_contact` + phone
- **Hotel confirmation** → `hotel_name`, `hotel_address`, `hotel_checkin`, `hotel_checkout`, `hotel_rooms`, `hotel_rate`, `hotel_currency`, `hotel_confirmation`, `hotel_block`, `hotel_block_size`, `hotel_block_rate`
- **Expense receipt** → creates row in `tour_expenses`. If category is Lodging/Accommodation/Hotel AND a show is matched, also writes total to `hotel_cost_actual` (stacks additively)
- **Deal memo** → creates or updates `tour_shows` record
- **Settlement** → writes to `tour_shows.settlement` JSONB
- **Contact list** → staged review → `shared_contacts` + `account_contacts`

### Show Matching
The intake API fetches all shows for the tour and sends them to Claude with the document text. Claude returns `{ showId, confidence, reason }`. If confidence > 0.5, the show is pre-selected in the review screen. The TM can always change the matched show before confirming.

## Finance Page — Expense Tabs

The finance page has expense category tabs: All, Transport, Fuel, Accommodation, Food, Gear, Misc, Merch, Promo, Other.

### All Tab
Shows all manual expenses. Also shows two summary strips at the top:
- **Hotel strip** — total hotel cost with actual/confirmed/projected breakdown + "See Breakdown →" button
- **Fuel strip** — estimated fuel (from route calculations) + actual fuel receipts side by side + "See Fuel →" button

### Accommodation Tab
Shows manual expenses tagged "Accommodation" PLUS a **Hotel Cost Breakdown** section (collapsed by default, expandable). The breakdown shows per-show hotel data with source flags (Actual / Confirmed / Projected).

### Fuel Tab
Shows manual expenses tagged "Fuel" (actual gas receipts).

### Transport Tab
Shows manual expenses tagged "Transport" PLUS the Transport Costs breakdown section (fuel estimate + flight costs from route calculations).

### Note on Fuel Receipts vs Estimated Fuel
Actual fuel receipts (dropped via drag-and-drop) go into `tour_expenses` with category "Fuel" and show in the Fuel tab. The estimated fuel cost from drive calculations (`fin.totalFuel`) is separate — it comes from `calcTourFinancials()`. **These two numbers do not yet combine into a single figure** — Tim needs to decide how actual fuel receipts should interact with the estimated fuel total before we wire that connection.

## Hotel Market Rate Table

Located in `lib/tourrouter/constants.ts` as `HOTEL_MARKET_RATES`. Covers ~130 cities across US, Canada, UK, Europe, and Australia with rates by star rating (2/3/4/5 star).

Regional fallbacks in `HOTEL_FALLBACK_RATES` cover any city not in the table.

The lookup helper is `getProjectedHotelRate(city, country, starRating)` in `lib/tourrouter/hotelRates.ts`.
